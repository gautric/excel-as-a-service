= Excel Engine by Quarkus

== Introduction

Excel-as-a-Service (EaaS) is a modern, distributed Excel computation engine that exposes Excel workbook calculations through multiple protocols including REST, gRPC, Kafka, and AWS Lambda. 
It enables organizations to leverage existing Excel business logic as scalable microservices without modifying the original spreadsheets.

image::https://github.com/gautric/excel-as-a-service/actions/workflows/eaas-ci-matrix.yml/badge.svg[]

== Build and Test

Only a JDK 21 is required: the Maven Wrapper downloads Maven 3.9.16 on first use.

    ./mvnw verify                          # build and run every test
    ./mvnw -pl excel-engine -am test       # one module and its dependencies

On Windows use `mvnw.cmd`.

    cd excel-rest
    ../mvnw quarkus:dev -Dexcel.static.resouces.uri=../sample

=== Endpoints

All paths are under `/eaas/api`.

[cols="1,3,2"]
|===
|Method |Path |Answer

|GET    |`/`                                         |list of resources
|GET    |`/{resource}`                               |resource (404 if unknown)
|POST   |`/{resource}` (multipart field `file`)      |201 Created + `Location`
|PUT    |`/{resource}` (multipart field `file`)      |201 created / 200 replaced
|DELETE |`/{resource}`                               |204 / 404
|GET    |`/{resource}/_download`                     |workbook, `ETag` (304 with `If-None-Match`)
|GET    |`/{resource}/sheets`                        |list of sheets
|GET    |`/{resource}/sheet/{sheet}`                 |sheet
|GET    |`/{resource}/sheet/{sheet}/cells`           |every cell
|GET    |`/{resource}/sheet/{sheet}/cell/{cell}?B2=TRUE` |one cell, computed with query inputs
|GET    |`/{resource}/sheet/{sheet}/compute`         |URI templates of the sheet API
|GET    |`/{resource}/sheet/{sheet}/compute/{OUT}/{IN}/{value}/...` |compute by `@input`/`@output` names
|POST   |`/{resource}/sheet/{sheet}/compute` (JSON)  |compute, see below
|POST   |`/compute` (JSON with `resource`, `sheet`)  |same, legacy
|===

Errors always use the same body, without stack trace:

  {"code": "400", "message": "Unknown output 'NOPE': not an @output name nor a cell reference"}

`404` unknown resource/sheet/cell, `400` invalid input or output, `500` unexpected error.

=== Compute with a JSON body

  curl -X POST -H 'Content-Type: application/json' \
    -d '{"inputs": {"PEP": true, "COUNTRY": "CY", "AMOUNT": 1000000}, "outputs": ["SCORE"]}' \
    http://localhost:8080/eaas/api/KYCAPI/sheet/ComputeKYC/compute

* `inputs` / `outputs` take `@input(NAME)` / `@output(NAME)` names, or cell references (`B2`, `Sheet!B2`).
* No `outputs`: every `@output` of the sheet is returned.
* `"global": true` enables cross-workbook references (loads every resource, so off by default; on by default for the legacy `POST /compute`).
* The same JSON (plus `resource`, `sheet`, `uuid`) is accepted by Kafka, gRPC and Lambda, which share one engine entry point: `ExcelEngine.compute(ExcelRequest)`.

Each computation works on a private copy of the workbook: concurrent requests never see each other's inputs, and formulas are never overwritten.

== Tips for Excel dev

* Include a default value into all Excel cells
** client can retrieve the value
** Excel engine can deal with the type of the cell

* Use only POI implemented functions
** https://poi.apache.org/components/spreadsheet/eval-devguide.html#Appendix+A+%E2%80%94+Functions+supported+by+POI[POI function available list]

== Configuration

.Configuration property
[%header,cols=4*] 
|===

|Properties
|Type 
|Default
|Comments

| `excel.static.resouces.uri`
| String
| `.`
| `classpath://` or _directory_ or _file_

| `excel.return.list.or.map`
| String/Enum
| `MAP`
| Return result into List (`LIST`) or Map(`MAP`)


| `excel.static.readonly`
| boolean
| `false`
| if `true` you cannot use POST method to add new file 

|===
